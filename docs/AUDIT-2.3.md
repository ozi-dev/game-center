# 2.3 review: changes, evidence and limits

This report follows the two external review lists and the actual-code findings supplied by the owner. Earlier claims that releases were absent or the Sunshine URL was broken were withdrawn by that reviewer; those were not treated as code defects. The existing pinned SHA-256 checks, ZIP traversal protection, atomic writes, conflict-aware backups and process-only ExecutionPolicy were retained and extended.

| Step | Change | Verification | Remaining limit |
| --- | --- | --- | --- |
| 1. Privilege boundary | Embedded executable broker; protected Program Files code and ProgramData state; immutable-in-GUI runtime digests and file leases; fixed operation list; SID/root binding; exact restore targets; unelevated user restore. Native helpers compiled before packaging. | Forged target/hash and outside-backup tests, owner/path/junction/lease checks, altered worker/manifest and injected-operation rejection. | First bootstrap/GUI remain unsigned; a wholly replaced application or compromised account is outside this guarantee. Fresh elevated/alternate-admin UAC still needs clean-VM review. |
| 2. Removal and repeat setup | New Uninstall action, protected ownership inventory, restore preflight, scoped task/firewall/shortcut/extension removal; opt-in owned Sunshine/ViGEm/device removal. Unknown/pre-existing/shared components preserved. | Real repeated apply/restore fixtures; Pester unowned/invalid-device tests; firewall all-rules preflight. | Driver store, shared VDD files, portable files and protected backup state deliberately need reviewed manual cleanup. Legacy user-writable records do not grant elevated ownership. No claim of an entirely automatic clean uninstall. |
| 3. Download trust | Fixed version/hash for all project-managed downloads; reviewed certificate thumbprints for signed Playnite/Sunshine/ViGEm/VDD; progress suppression and bad/interrupted .part deletion. | Actual cached signatures inspected; pinned VDD archive hash and its extracted catalog signer verified; valid wrong signer and wrong hash regression tests. | Optional WinGet/vendor clients auto-update separately. Certificate rotations need maintainer review. Signing SofaRelay itself awaits provider/owner approval. |
| 4. Reproducible release | Central VERSION, pinned Roslyn /deterministic+, path mapping, sorted ZIP entries/fixed timestamps; tag build/test workflow, ZIP SHA256SUMS, GitHub provenance and changelog notes. Old assets never clobbered. | Local rebuild/package comparison and full payload hash validation; CI records and published attestations are the release evidence. | Reproducibility assumes same source/SDK/Windows toolchain/line endings; provenance proves workflow origin, not software safety. Timestamped future signatures change bytes. |
| 5. Recovery and security defaults | Optional limited-user watchdog at sign-in; confirmed-idle policy; LAN-only Sunshine and exact-executable Private/LocalSubnet rules; no default password or router changes. File and task/firewall transactions handle caught errors. | Core crash/reboot-sign-in/active/unknown policy simulations; rollback and firewall preflight fixtures. | Actual physical recovery, abrupt power loss, reboot/driver crash and Shield high refresh/HDR require device/VM checks. No pre-login guarantee; unknown state delays recovery. Broad unrelated firewall policy is not audited. External prerequisite installs can remain after later failure. |
| 6. Code quality/privacy | Worker split by function, library-update errors reported, untranslated device validation fixed, four-language parity, pinned PSScriptAnalyzer/Pester, actual Diagnostics action export check, Windows 2022/2025 matrix, link and weekly upstream checks. | 29 core, 2,062 localization, backend and Pester checks; actual redacted export; curated analyzer rules. | Automated code tests are not an independent human line-by-line security audit. Raw local logs can contain personal data; exported files still deserve review. |
| 7. Documentation and support | Four-language README/guide additions, checksum/provenance/SmartScreen instructions, trust/signing model, troubleshooting, ownership-aware uninstall and upstream-pin table. Required diagnostic-export-or-error issue field. | Public source allowlist, local links/anchors and language navigation; weekly public URL review. | Four-language wizard screenshots of older pages predate the new 2.3 controls. Physical Shield/TV behavior and account login remain first-use checks. |

The historical 2.1.0 and 2.2.0 releases were both made on 2026-11-16. Their dates and original titles are retained as release history rather than rewritten to create artificial chronology. Legacy `GamingCenter*` Playnite IDs remain stable intentionally so existing libraries, profiles and playtime state continue to resolve.

Local unsigned reproducibility check: independent output directories produced matching hashes for seven binaries and byte-identical ZIPs; all 382 listed payload checksums were verified. The final release is rebuilt in CI from its tag rather than reusing that local test ZIP.
